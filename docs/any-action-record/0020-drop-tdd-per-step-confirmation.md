# 0020: TDDワークフローから各ステップの確認を廃止した

- Date: 2026-09-04
- Related AnyDR: 0069

## Objective

AnyDR 0066（TDDワークフローを5ステップに分割し各ステップ完了ごとに状況報告・確認を挟む運用）を
Issue #7の実装で実際に1サイクル運用した直後、ユーザーから「随時確認は不要、いちばん最後にサマリ
だけ教えてほしい」という明示的な指示があり、これを反映する。

## Action

CLAUDE.mdの「開発ワークフロー（TDDサイクルの徹底）」から「各ステップの完了後、次のステップに
進む前に必ず状況を報告し、確認を待ってください」という一文を削除し、「各ステップごとの確認は
不要。5ステップを通しで実行し、完了後にまとめてサマリを報告してください」に置き換えた。5ステップ
という構造自体（テストコード作成→スケルトン実装→振る舞いのRED確認→GREEN実装→リファクタリング）
は維持した。AnyDR 0069として記録した。

## Result

CLAUDE.md更新・AnyDR 0069をコミット（`fe51855`）。

## Reflections

導入したばかりの厳格なプロセス（AnyDR 0066）が、実際に1サイクル運用しただけですぐに見直しの
対象になった。「理屈の上で良さそうなプロセス」と「実際にやってみて心地よいプロセス」は別物で
あり、新しい運用ルールは短いサイクルで実際に試してからでないと、その運用コストの実感が掴めない
という教訓になった。
