# 0037: Issue #17（課金機能）を設計し、Firebase/RevenueCatのセットアップに着手した

- Date: 2026-09-13
- Related AnyDR: 0112〜0125
- Related Issue: #17, #32, #33

## Objective

Issue #17（RevenueCat SDK導入と有料プラン実装）を`/grill-with-docs`で設計し、B案（回数制
フリーミアム）の未確定パラメータを確定させた上で、実装をsub-issueに分割し、外部サービス
（Firebase/RevenueCat/Play Console）側のセットアップに着手する。

## Action

*   AnyDR 0055のフィードバック実証型プロセスに従い、無料枠の月間回数はX/Discordでの
    問いかけ結果（「10回だとユーザーが課金前に満足してしまう」という理由付きで月5回）を
    採用（AnyDR 0112）。残り2パラメータ（価格帯・アップセルのタイミング）は、Play申請
    目標09-20まで残り7日というスケジュールを踏まえ、追加の問いかけをせずAnyDR 0036の
    参考値をデフォルト採用する方針に切り替えた（AnyDR 0113）。
*   価格を月額480円・年額3,600円に確定（AnyDR 0114）。アップセルは利用のたびに残り回数を
    Snackbarで表示する方式に決定（AnyDR 0115, 0120）。カウンターリセットは暦月とした
    （AnyDR 0116）。
*   設計の途中で、BYOKを使わない全ユーザー（無料枠・購読ユーザー）が、そもそも開発者の
    Gemini APIキーをどう使うのかが一切決まっていないという大きな設計漏れが発覚。クライアント
    埋め込み案・サーバーレス関数案・「アプリのAI機能を購読する」という価値提案自体の撤回案の
    3案を比較し、サーバーレス関数（Firebase Cloud Functions、Node.js/TypeScript）を新設する
    方針を採用（AnyDR 0121, 0122）。ユーザー識別はFirebase Auth匿名認証のUID＝RevenueCatの
    `app_user_id`とし（AnyDR 0123）、この前提変化により無料枠カウンターの保存先もローカル
    （AnyDR 0117）からサーバー側Firestoreへ方針転換した（AnyDR 0124、0117自体は編集せず
    Relatedでリンクする形で撤回）。
*   Gemini 3.5 Flashの実コスト（$1.50/$9.00 per 1M tokens）を基に採算試算を実施。無料枠
    ユーザーのコストは無視できる規模で、有料ユーザー1人で無料ユーザー70〜90人分をカバー
    できる余裕があることを確認。ヘビーユーザーによる逆ザヤの懸念から有料プランへの上限
    導入も検討したが、テールリスクに対して核となる価値提案（無制限）を弱める方が損だと
    判断し、無制限のまま維持することにした（AnyDR 0125）。
*   Issue #17を5つのsub-issue（#33〜#37）に分割し、依存関係を設定。Issue #32
    （ローカルカウンターの再インストール回避）はAnyDR 0124により解消見込みとなった。
*   Issue #33（Firebase/RevenueCatのプロジェクト・商品設定）に着手。Firebaseプロジェクト
    作成、Firebase Auth匿名認証有効化、Firestore作成（デフォルトの全拒否ルールを維持、
    Cloud Functions経由のみのアクセス設計のため）、RevenueCatアカウント・Androidアプリ
    登録、Google Cloud側のサービスアカウント作成とJSONキー発行、Play Console側での
    サービスアカウントへの権限付与まで完了。RevenueCatでの認証情報検証は「最大36時間の
    伝播待ち」という想定内の状態で保留。Play Console側でサブスクリプション商品を作成
    しようとしたところ「作成」ボタンが表示されず、調査の結果お支払いプロファイルの
    受け取り方法（銀行口座）が未登録だったことが判明し登録したが、「確認待ち」ステータスの
    ままボタンは依然として表示されず、原因の確定には至らなかった。

## Result

*   AnyDR 0112〜0125（14件）を記録。
*   GitHub Issue #33〜#37を作成し、#17のsub-issueとして依存関係付きで紐付け。
*   Firebase/RevenueCat/GCPのアカウント・プロジェクト設定を大部分完了。Play Console側の
    サブスクリプション商品作成のみ、銀行口座確認待ちのため保留中。

## Reflections

「有料ユーザーだけでなく無料ユーザーも、BYOKを使わない限りアプリが誰かのAPIキーで
Geminiを呼ぶ必要がある」という、当初のAnyDR 0036の時点では意識されていなかった要件が、
実装直前のグリルで初めて発覚した。B案・C案という当初の比較軸（無料枠の実装コストの
大小）は、この「非BYOKユーザー向けのAPIキー問題」という、より根本的な前提を素通りして
いたことになる。マネタイズ戦略のような早期の意思決定ほど、後工程で技術的な前提条件が
覆ることがあるという教訓を得た。

また、Play Consoleの「定期購入の作成ボタンが出ない」という問題は、結局明確な原因確定に
至らなかった。今セッションで何度も経験した「Play ConsoleのUIについての記憶や一般論は
古い/不正確なことがある」という教訓通り、公式ドキュメントを検索しても核心の原因（銀行
口座の確認待ちが本当にブロッカーなのか）は特定できず、最終的には「時間を置いて再確認する」
という保留判断に落ち着いた。すべての外部サービスの不具合がその場で解決できるとは限らず、
無理に粘らず次の作業に切り替える判断も必要だと再確認した。
