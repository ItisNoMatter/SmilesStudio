# 0010: Shipaton 2026参加を決定しAndroid対応・Koog MVP・課金・OSS戦略の方針を確定

- Date: 2026-09-02
- Related AnyDR: 0027, 0028, 0029, 0030, 0031, 0032, 0033

## Objective

RevenueCat主催のモバイルアプリハッカソンShipaton 2026への参加を受け、デスクトップ専用だった
プロジェクトの方針をAndroid対応にどう広げるかを一連の決定として確定する。

## Action

共有されたShipaton 2026対応方針ドキュメントを踏まえ、公式ルール（Devpost）をWebSearch/
WebFetchで調査した上で、`android-app`モジュールの追加（0027）、手描き構造式画像→Koog経由の
Vision LLM→SMILES変換というMVP機能スコープ（0028）、Vision LLMのデフォルトプロバイダを
Geminiにしつつ Koog のマルチプロバイダBYOKは維持（0029）、BYOKハイブリッド課金モデル
（0030）、型システムをOSSコントリビューション安全網とする戦略（0031）、AIレビューCIは低
優先度（0032）を決定・記録した。既存のデスクトップv1ロードマップ（Issue #1）とは別に、
Shipaton対応を独立したWayfinderマップIssue（#11）として管理する方針も確定した（0033）。

## Result

7件のAnyDR（0027-0033）が確定し、`c2475b7`・`a6d5c19`でコミットした。新しいWayfinderマップ
（Issue #11）とその子Issue群が作成され、デスクトップv1ロードマップと並行する2本目のロードマップ
として走り出した。

## Reflections

「AtomId安定性は未定義」（0007）のような、実装を先送りしただけに見えた過去の決定が、今回
グラフィカル編集を避け続けるv1方針（0017）と地続きだったことに改めて気づいた。ハッカソンという
外部要因による大きな方針転換でも、既存アーキテクチャ（KMPモジュール構成、0002）が土台として
そのまま活きた。
