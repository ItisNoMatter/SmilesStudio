# 0017: 作業計画をストア審査優先の段階的リリースに見直した

- Date: 2026-09-04
- Related AnyDR: 0059, 0060, 0061, 0062, 0063
- Related Issue: #18, #19, #21, #22, #23

## Objective

「MVPでストアの審査を通すことを最優先事項とし、そのあとに課金の導線などをつくっていく形にしたい。
また、何日までにどのissueが終わっているべきかを考えてマイルストーン設置したい」というユーザーの
依頼を受け、Shipaton 2026対応のリリース戦略とIssue構成を見直し、具体的な期日を設定する。

## Action

`/grill-with-docs`でグリリングセッションを実施した。リリース戦略を段階的リリース（最小ビルドを
先に完成させ審査クロックを早期開始）に転換し（AnyDR 0059）、最小ビルドのスコープをレンダリング
パイプライン（#6/#7）＋モバイル調整（#13）のみに確定した（AnyDR 0060）。この過程でWebSearchに
より、Google Playの新規個人開発者アカウントには本番公開の前に「12人以上のテスターによる14日間
連続の非公開テスト」が別途必須であることを発見し、ユーザーに確認したところSmilesStudio用の
アカウントもこの要件が適用されることが分かった。この事実を受け、当初計画していた「初回申請→
機能追加版申請」の2回本番提出を、「非公開テスト14日間を機能開発と並行させ本番提出は1回のみ」
に見直した（AnyDR 0061〜0062）。マイルストーンはフェーズ単位（3個）で設置する方針を確定し
（AnyDR 0063）、具体的な期日（Phase 1: 09-08、Phase 2: 09-22、Phase 3: 09-28）を提示・確認した。

実装として、Issue #18を「Google Play非公開テストの開始・運用」に再定義し名称・本文・依存関係
（#6/#7/#13）を更新、新規Issue #23「本番申請（機能追加版）」を作成しmap #11のsub-issueとして
登録、Issue #19・#21の依存関係を#23（＋#19は#22も）に付け替えた。GitHubマイルストーンを3個
作成し期日を設定、該当Issueを割り当てた。Issue #1・#11のマップ本文も今回の決定内容で更新した。

## Result

AnyDR 0059〜0063を記録・コミット（`a1c5372`）・push完了。GitHub Issue構成（#18再定義、#23
新設、#19/#21/#22の依存関係付け替え）とマイルストーン3個（Phase 1/2/3）の設置が完了した。

## Reflections

実装過程で、GitHubのissue dependencies APIの`DELETE .../blocked_by`エンドポイントはブロッカー
のissue_idをリクエストボディではなくURLパス末尾に指定する必要があることが判明した（ボディ指定
では404になった）。また、Issue #18の依存関係を付け替える際、`gh issue edit`によるタイトル・
本文の変更だけでは依存関係グラフは一切変わらないことを見落とし、旧ブロッカーが残ったまま新
ブロッカーを追加してしまうミスをしたが、後で検証して発見・修正した。

より大きな気づきとして、ユーザーの「ストア審査を最優先」という要望を事実調査なしに字面通り
実装していたら、実際のボトルネック（14日間の非公開テスト要件）を見落とし、無駄に2回の本番
提出を計画するところだった。グリリング中の事実発見が、既に確定していたはずの決定（AnyDR
0059〜0061）を後から修正する結果になったのは、fact-findingを後回しにせず早い段階で行うことの
重要性を示している。
