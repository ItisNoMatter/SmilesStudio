# 0033: スクリーンショットの比率超過を修正し、フィーチャーグラフィックを追加した

- Date: 2026-09-07
- Related Issue: #26（クローズ後の追補）

## Objective
Issue #18のPlay Console実操作を案内する前に、ストア掲載素材（Issue #26で準備済み）が
実際にアップロード可能な状態かを確認し、不備があれば解消する。

## Action
Google Playのストア掲載要件を調べ直したところ、スクリーンショットは縦横比が最大2:1
までという制約があることが分かった。Issue #26で用意した既存のスクリーンショット
（1080x2400）は比率2.22:1でこの上限を超えており、実際にアップロードすれば拒否されて
いた可能性が高い。また、必須素材である「フィーチャーグラフィック」（1024x500）が
Issue #26の時点で漏れていたことにも気づいた。

Python（PIL）でスクリーンショットを1080x1920（16:9）にクロップ: ホーム画面は空白の
Canvas領域から480px分を除去してつなぎ合わせ、使い方タブは単純に上から1920pxを切り出す
方式にした（最初、使い方タブも同じ「中間を除去してつなぎ合わせる」方式を試したところ
カードの途中で不自然な継ぎ目ができてしまい、単純な上端クロップに変更した）。

フィーチャーグラフィックは、アプリアイコンと同じ六角形（ベンゼン環）モチーフ＋
アプリ名＋一言説明をPILで直接描画して作成。24-bit PNG（アルファなし）であることを
確認した。

## Result
*   コミット 7c25d8e をpush。
*   スクリーンショット2枚（1080x1920、16:9）・フィーチャーグラフィック（1024x500）が
    Play Consoleの制約を満たす状態になった。

## Reflections
Issue #26を一度closeした後に、実際のアップロード要件（比率制限・フィーチャーグラフィック
必須）を再調査して初めて不備に気づいた。「素材を作った」ことと「実際にPlay Consoleが
受け付ける形式になっている」ことは別物で、closeする前に一次情報（Google公式のストア
掲載要件）を確認しておくべきだった、という反省点。今回は次の作業（Play Console実操作の
案内）に進む直前に確認したため大きな手戻りにはならなかったが、この種の「外部サービスの
形式的要件」はドキュメントを読んだ気になって見落としやすいポイントだと感じた。
