# 0014: buildinpublic-tweet Skillを設計・実装し初めて実際にツイート下書きを作成

- Date: 2026-09-03
- Related AnyDR: 0039, 0040, 0041, 0042, 0043, 0044

## Objective

AnyDRで記録した設計判断を#BuildInPublicハッシュタグ向けに共有するための、ツイート下書き作成
Skillを新設する。

## Action

`/grill-with-docs`でSkillのスコープをグローバル配置・英語AnyDR用の`en/`サブディレクトリ・
明示呼び出し専用（プロアクティブ発火はしない）・英語限定ツイート・ハッシュタグとトーンの
規約・ベストエフォートのクリップボードコピーという6点で確定した（AnyDR 0039-0044）。実装後、
`/buildinpublic-tweet 0028`で実際にAnyDR 0028のツイート下書きを作成し、AnyDR 0028の英訳を
`docs/any-decision-record/en/`に新規生成した。

## Result

`~/.claude/skills/buildinpublic-tweet/`（グローバル）が完成した。AnyDR 0028の英訳
（`13427e8`）と初回のツイート下書きが生成された。

## Reflections

初回のツイート下書きは280文字制限に収めようとして電報のような読みにくい英語になってしまい、
ユーザーから「文字数に圧縮しようとして読みづらい英語になってない？」と直接フィードバックを
受けた。文字数に収めることを優先するあまり「なぜその決定をしたか」という中身が犠牲になって
いたと気づき、自然な文章を先に書いて実際に超過した場合のみ削る、という順序にSkillの指示自体を
修正した。文字数制約は目的ではなく制約に過ぎないという当たり前のことを、実際に一度失敗して
初めて仕組みに落とし込めた。
