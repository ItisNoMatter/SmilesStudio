# 0036: 課金導線をB案（回数制フリーミアム）/C案（即ペイウォール）に一本化し、BYOKハイブリッドモデル・トライアルを廃止する

- Date: 2026-09-03
- Status: Accepted
- Category: architecture
- Deciders: the user

## Context

[[0030]]で「無料プラン=自分のAPIキーで無制限、有料プラン=アプリ提供キー+1週間の無料トライアル」というBYOKハイブリッドモデルを採用していた。ユーザーから更新版のShipaton 2026対応方針が共有され、実装確実性を優先して複数案を比較検討した結果、方針が変更されたことが判明した。トライアルの扱いが更新版の説明から欠落していたため、本セッションで確認したところ、トライアルは廃止されB/Cの回数制・即ペイウォールに一本化する方針であることが確定した。

## Decision

課金導線をB案またはC案のいずれかに一本化する（開発が順調ならB、期限が厳しくなればCにフォールバック）。1週間の無料トライアルは廃止する。

- **B案（回数制フリーミアム）**: 無料で月あたり一定回数までKoog機能（手描き構造式認識）を利用可能。超えたら課金またはBYOKに切り替え。トライアル日付管理が不要でカウンター管理のみで済むため実装が軽い。
- **C案（即ペイウォール）**: 無料版はSMILES直接入力のみで、Koog機能は最初から課金またはBYOK必須。状態管理がほぼ不要で最も実装が単純。

いずれの案でも、BYOK（ユーザー自身のAPIキー利用）は引き続き課金を回避する手段として提供する。ダークパターン（意図的な遅延・広告表示）は不採用のまま。RevenueCat SDKで実装する。設定画面で「BYOKを使う」か「アプリのAI機能を購読する」かを選べる導線も維持する。

## Alternatives

- [[0030]]のBYOKハイブリッドモデル（無料=BYOK無制限、有料=アプリ提供キー+1週間トライアル）: 開発者の推論コスト負担を利用者側に委ねられるという利点があったが、トライアルの日付管理・トライアル終了通知等、実装すべき状態管理が多く、ハッカソンの短い期間内での実装確実性を優先した結果、より単純なB/C案に置き換えられた。

## Consequences

- B案を採用した場合、無料枠の利用回数カウンターの実装が必要になる（RevenueCatまたは自前でのカウンター管理）。
- C案にフォールバックした場合、状態管理はほぼ不要になるが、無料版のユーザー体験（Koog機能を一切試せない）はB案より制限的になる。
- トライアル関連のUI（トライアル終了通知等）は不要になった。[Issue #17「RevenueCat SDK導入と有料プラン実装」](https://github.com/ItisNoMatter/SmilesStudio/issues/17)のスコープをこの決定に合わせて更新する。
- 価格帯（月額300〜500円、年額2,000〜3,000円程度）は引き続き未確定の参考値のまま。
