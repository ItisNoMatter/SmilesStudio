# 0017: v1のコア体験をテキスト編集＋読み取り専用の構造式描画に限定する

- Date: 2026-09-01
- Status: Accepted
- Category: architecture
- Deciders: the user, Claude Code

## Context

「プロジェクト全体の進め方の構想を整理してissue化したい。最小構成でユーザーにリリースできるところまで」というゴールに向けたグリリングセッションの中で、v1のコア体験（インタラクションモデル）を最初に確定する必要があった。CLAUDE.mdはアプリを「SMILES記法エディタ＆構造式描画ツール」と説明しており、「エディタ」という語がテキストレベルの編集（SMILES文字列の入力・修正）を指すのか、Canvas上での原子・結合の直接的なグラフィカル編集を指すのかが曖昧だった。

## Decision

v1のコア体験は「テキスト編集＋読み取り専用の構造式描画」とする。ユーザーはテキストフィールドにSMILES文字列を入力・編集し、パース結果（`Molecule`）をCanvasに静的に描画する。Canvas上での原子・結合の直接編集（クリックやドラッグによるグラフィカルな構造操作）はv1のスコープに含めない。

## Alternatives

- グラフィカルな構造エディタ（Canvas上で原子・結合をクリック/ドラッグして直接構造を組み立て、SMILES文字列は表示/エクスポート用の副産物とする）: 「エディタ」の名には最も忠実で、化学徒に馴染みのあるUX（ChemDrawなど）が得られる一方、AtomId安定性（[[0007]]で未定義）を今すぐ設計・実装する必要がありスコープが一気に膨らむ。ヒットテスト・ドラッグ操作・Undo/RedoなどCompose Canvas上のインタラクション設計も新規に必要で「最小構成」から外れる。さらに逆方向（Molecule→SMILES）シリアライザが先に必要になり、[[0009]]（正規SMILESライター実装の先送り）と衝突するため不採用。ただし破棄ではなく、将来タスクとして保留する。

## Consequences

- v1のスコープは「描画ロジックの実装」に絞られる。既存の`SmilesParser`・`Molecule`・空の`MoleculeCanvas`をほぼそのまま拡張する形で進められる。
- [[0007]]（AtomId安定性未定義）・[[0009]]（SMILESライター実装の先送り）は、いずれも「グラフィカル編集は今やらない」という前提を維持したまま有効であり続ける。
- グラフィカルな構造エディタ（アプローチB）は破棄ではなくv2以降の拡張候補として保留する。将来実装する際は[[0007]]と[[0009]]を再訪する必要がある。CLAUDE.md記載の将来のKoog連携（手描き構造式→SMILES認識）とも接続する拡張として位置づけられる。
