# 0125: 有料プランは上限を設けず無制限のまま維持する

- Date: 2026-09-13
- Status: Accepted
- Category: rejected
- Deciders: the user, Claude Code

## Context

AnyDR 0114の価格（月額480円）とGemini 3.5 Flashの実コスト（$1.50/$9.00 per 1M tokens）を
突き合わせた採算試算を行った結果、現実的な利用強度（月10〜30回）では有料ユーザー1人が
無料ユーザー70〜90人分のAPIコストを賄える大きな余裕があることが分かった。一方、コスト単価の
見積もりを5倍（¥5/回）に引き上げ、かつ有料ユーザーが月100回級のヘビー利用をした場合、
その1人単体では逆ザヤ（純利益がマイナス）になるシナリオも試算上判明した。この結果を受けて、
有料プランにも利用回数の上限を設けるべきか検討した。

## Decision

有料プランには上限を設けず、無制限のまま維持する。

## Alternatives

- 有料プランに明示的な月間上限を設ける（例: 「月100回まで」と謳う）: 採算リスクを最も
  確実に防げるが、「購読すれば無制限」という価値提案が崩れ、BYOK（本当に無制限にしたい
  人向けの既存の選択肢）との差別化も薄れるため不採用とした。
- 表向きは「無制限」を謳いつつ、裏側で非常に高い上限（例: 月500回）を設け悪用のみ防ぐ:
  マーケティング上の訴求力を保てる利点はあるが、「無制限と言いながら実は上限がある」という
  開示上のグレーゾーンが生じ、実装コストの割に防げる範囲が極端な悪用ケースのみと限定的で
  あるため不採用とした。

サブスクリプションは個々のユーザー単位ではなく全体プールで採算を見るのが通常のモデルであり、
逆ザヤシナリオは「コスト見積もりを5倍」かつ「月100回のヘビー利用」という二重に厳しい前提
でしか発生しないテールリスクである。試算で判明した大きな余裕（有料1人で無料70〜90人分を
カバー）を踏まえ、この稀なリスクのために核となる価値提案（無制限）を弱めるべきではないと
判断した。

## Consequences

- 有料プランの実装（RevenueCatのエンタイトルメント判定）はシンプルなまま（回数カウンター
  管理が不要）で済む。
- 極端な外れ値ユーザーが実際に多発した場合は、この判断を再考する必要がある。
