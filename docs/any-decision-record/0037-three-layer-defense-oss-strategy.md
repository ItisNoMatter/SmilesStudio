# 0037: OSS戦略を「三層防御」構想に拡張し、標準装備の期待値テストハーネス層を追加する

- Date: 2026-09-03
- Status: Accepted
- Category: architecture
- Deciders: the user

## Context

[[0031]]で「型システムをAI支援コントリビューションの安全網とする」OSS戦略を採用し、[[0032]]でPR向けAIレビューCI（低優先度）を記録した。ユーザーから更新版のShipaton 2026対応方針が共有され、この2つを「三層防御」という明示的な構想に統合し、新たに3層目（クローン直後から機能する標準装備のテストハーネス）を追加する方針が示された。インスピレーション元はDroidKaigi/conference-appシリーズの、Robotパターンによるテストハーネス標準装備・Gradle convention pluginsによるモジュール境界強制・CI必須チェックという設計思想。

## Decision

「化学の専門知識はあってもプログラミング経験の少ない人でも、バイブコーディングで安全にコントリビュートできる」という狙いを、単なる型安全アピールに留めず、「不完全なコードをそもそも通さない」仕組みを多層で標準装備する「三層防御」として明示的にフレーミングする。

1. **型システム（コンパイル時）**: [[0031]]の内容そのまま。「書く前に防ぐ」層。
2. **AIレビュー（PR時）**: [[0032]]の内容そのまま。「出した後に検出する」層。優先度は他タスク完了後の「余力があれば」枠のまま変更なし。
3. **標準装備のテストハーネス（クローン直後）**【新規】: リポジトリをクローンした時点で、既知の化合物（ベンゼン、エタノール等）に対する期待値テストが組み込まれており、これを通さないとCIが通らない仕組み。「そもそも逸脱した実装をしにくくする」層。ハッカソン期間内ではDroidKaigiのRobotパターンのような大規模な仕組みは目指さず、化学構造の期待値テストが数個CIに組み込まれているミニマムなプロトタイプに留める。

README/デモでは、この三層防御の思想をフレーミングとして前面に出す（3層目が最小実装であっても、思想の完成度は伝わる設計とする）。

## Alternatives

本文中に代替案の比較記述はなし。型システム単体のアピール（[[0031]]時点の狭いフレーミング）から、三層構造への拡張は、既存の2層（型システム・AIレビュー）に新たな1層を足す形の純粋な追加拡張であり、既存決定の破棄ではない。

## Consequences

- [[0031]]・[[0032]]は本AnyDRの「三層防御」構想における層1・層2として引き続き有効。内容の変更はない。
- 新たに「標準装備のテストハーネス」実装タスクが必要になる。優先順位はRevenueCat課金実装の後、ストア公開準備の前（ユーザー提示の優先順位リストの4番目）。マップIssue #11に対応する子Issueを追加する。
- README/デモ資料の作成時、三層防御を明示的なフレーミングとして使用する（[Issue #19「Devpost提出物準備」](https://github.com/ItisNoMatter/SmilesStudio/issues/19)に反映）。
