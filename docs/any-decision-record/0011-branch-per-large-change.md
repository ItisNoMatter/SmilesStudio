# 0011: 大きめの変更の時だけブランチを切る運用にする

- Date: 2026-08-31
- Status: Accepted
- Category: process
- Deciders: the user, Claude Code

## Context
個人開発（レビュアー不在）のこのプロジェクトで、ブランチを切ってPRを出す運用に変えるべきか
ユーザーから相談があった。Claude Codeは、個人開発ではPR本来のメリット（他者レビュー）が
得られないため常時ブランチ運用に固定する必要はないが、`/code-review ultra`のようなAIレビューを
かけたい時や、Koog連携のような大きめの実験的変更を`main`から切り離して試したい時に限って
トピックブランチを切るハイブリッド運用を提案し、ユーザーがこれを採用することにした。

## Decision
通常の変更は現状通り`main`ブランチに直接コミットして進める。ただし、大きめの変更（大規模な
機能追加や、`main`から切り離して試行錯誤したい実験的変更など）や、`/code-review ultra`のような
ブランチ前提のAIレビューをかけたい変更に限り、トピックブランチを切ってPRを出す。

## Alternatives
- **常時ブランチ+PR運用に統一する**: 個人開発でレビュアーが不在のため、PRの本来的なメリット
  （他者レビュー）が得られず、ブランチ作成・マージのオーバーヘッドだけが増えるため不採用。
- **常に`main`への直接コミットのみ（ブランチを一切使わない）**: 実験的な大きな変更を試したい
  場合に`main`の安定性を損なうリスクがあり、`/code-review ultra`のようなブランチ前提の機能を
  活用できなくなるため不採用。

## Consequences
「大きめの変更」の具体的な基準（変更行数、モジュール跨ぎの有無、リスクの大小など）は
今回は厳密に定義しておらず、着手時にケースバイケースで判断する。判断に迷うケースが
積み重なってきた場合は、改めて具体的な基準を別のAnyDRとして定義し直す可能性がある。
